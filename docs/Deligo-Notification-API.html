Deligo Notification API

One request. Deligo sends a customer notification through the delivery map service — by status id, from a template, or with your own wording — and gets back exactly what the customer saw.
deligo-service · POST /api/notifications/send · supersedes the Notification Playbook and the Receiver Spec
Монголоор товчхон. Deligo талаас хэрэглэгч рүү мэдэгдэл илгээхэд нэг л API дуудна: POST /api/notifications/send. Гурван хэлбэрийн аль нэгээр: status_id өгвөл тухайн төлөвийн мэдэгдэл шууд явна (хамгийн энгийн); бэлэн загвар (event_type) сонгох; эсвэл өөрийн title/body бичих. 2. Request

POST /api/notifications/send

Send exactly one of: a status (status_id), a template (event_type), or your own copy (title + body). Two at once, or none, is a 422.

Simplest call: {"sales_id": "…", "status_id": 14}. Sends exactly what a driver setting wfm 14 would send — same rule table, same wording, operator edits included. Nothing else to fill in.
FieldTypeMeaning
sales_idstringrequiredThe order. Same id your /api/sales/* endpoints key on.
sales_numberstringoptionalHuman-facing order code — used in the tracking link and {sales_number}. Looked up from the order when omitted; falls back to sales_id.
Status mode
status_idintegerone ofDeligo wfm status id (3, 8, 12–17, 23, …). The service picks the template the way it does for a driver's status change — see §6. Unknown ids get the generic status_changed.
status_descriptionstringoptionalDriver's / operator's note. Only the generic templates (delivery_failed, status_changed) print it, as a trailing “Тайлбар: …”.
Template mode
event_typestringone ofWhich template — see §6.
paramsobjectoptionalValues for the template's placeholders — see §3. Only needed when the template has any.
Custom mode
titlestringone of1–120 chars. Shown exactly as sent.
bodystringone of1–400 chars. Shown exactly as sent.
Both modes
iconstringoptionalMaterial Symbols name (local_shipping, campaign, …). Template's own icon by default; campaign in custom mode.
urgencystringoptionallow | normal | high. high keeps the notification on screen until dismissed. Template's own by default; high in custom mode.

3. Template params

Most templates need nothing. The ones that print a status, a note or a queue position need the value to print. Send the raw value; the service derives the sentence fragment.

You sendWe deriveUsed by
wfm_status_id (int)status_label — the Mongolian status namedelivery_failed, status_changed
status_descriptionstatus_description_line — “ Тайлбар: …” or emptydelivery_failed, status_changed
queue_position (int)queue_position_text — “2 хүргэлтийн дараа хүргэгдэхээр байна”delivery_queue_near
distance_text—driver_nearby
formatted_address, changed_by_name—address_updated
Missing placeholder = 422, not a blank sentence. If a template needs {queue_position_text} and you sent no queue_position, the request is rejected with the missing names listed. Nothing goes to the customer. A key not in the table above is also a 422 — typo protection.

4. Response

200 OK. The title/body are the exact strings the customer sees — write them to the order timeline as-is.

{
  "status": "ok",
  "data": {
    "event_id":     "9f2c1ab34de84f0197c5b1d0a6e2f8ce",
    "sales_id":     "1773113766311954",
    "sales_number": "ORD-77",
    "event_type":   "delivery_failed",
    "title":        "Хүргэлт амжилтгүй боллоо",
    "body":         "Таны захиалгын төлөв: Хаягаар очсон. Тайлбар: Хаалга нээгээгүй",
    "icon":         "error",
    "urgency":      "high",
    "tracking_url": "https://map.deligoalpha.mn/track/ORD-77",
    "push_devices": 2,
    "push_enabled": true,
    "sent_at":      "2026-09-11T03:18:16.129678+00:00"
  }
}
FieldMeaning
event_id32-char hex, unique per notification. Store it — it is the key in our delivery log if you ever need to ask about one.
event_typeWhat was sent. Status mode reports the template the status resolved to; custom mode reports admin_message.
title, body, icon, urgencyRendered. No placeholders left.
tracking_urlPage the notification opens when tapped.
push_devicesBrowsers registered for push on this order. 0 is normal — the customer may still see it in an open tracking tab. Not a failure.
push_enabledWhether web push is configured on the server at all. false = open tabs only.
sent_atISO-8601 UTC.

5. Errors

CodeWhendetail
403Wrong X-API-KeyInvalid or missing API key
404Unknown event_typeLists every known type
409status_id an operator has muted in the admin panelNothing was sent
422More than one mode / none; title without body; length limits; bad icon/urgency; unknown params key; missing placeholderSays which

Anything not 200: nothing was sent. Safe to fix and retry.

7. Copy-paste examples

By status — the simplest

curl -X POST "$BASE/api/notifications/send" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "sales_id": "1773113766311954", "status_id": 14 }'

By status, with the driver's note

curl -X POST "$BASE/api/notifications/send" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sales_id": "1773113766311954",
    "status_id": 16,
    "status_description": "Хаалга нээгээгүй"
  }'

Template, no params

curl -X POST "$BASE/api/notifications/send" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sales_id": "1773113766311954",
    "sales_number": "ORD-77",
    "event_type": "delivery_completed"
  }'

Template with params

curl -X POST "$BASE/api/notifications/send" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sales_id": "1773113766311954",
    "sales_number": "ORD-77",
    "event_type": "delivery_failed",
    "params": { "wfm_status_id": 16, "status_description": "Хаалга нээгээгүй" }
  }'

Your own wording

curl -X POST "$BASE/api/notifications/send" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sales_id": "1773113766311954",
    "sales_number": "ORD-77",
    "title": "Хүргэлт хойшиллоо",
    "body": "Жолооч 30 минутын дараа очно.",
    "icon": "campaign",
    "urgency": "high"
  }'

8. How it reaches the customer

1
Deligo calls this endpoint
POST /api/notifications/send
2
Open tracking tab
SSE, within ~1 s
3
Closed tab / phone
Web Push (if the browser opted in)
4
Response to Deligo
rendered copy + event_id
  • Same road as every automatic notification — one code path, one log.
  • The customer's browser opts in to push on the tracking page itself; Deligo does nothing for that.
  • One notification per order per event_type replaces the previous one in the phone's tray rather than stacking. Sending delivery_completed twice shows once.
  • status_id mode sends the notification only — it does not change the order's status. Use POST /api/auth/orders/changestatus for that; it notifies on its own.
  • No outbound call from us to Deligo. The old POST /api/sales/notification report is switched off; the response above is the record.
