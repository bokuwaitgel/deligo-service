1. Overview

A customer tracking an order is told three things, in this order: the driver has their goods, the driver is nearly at them, and how it ended. Everything else is a variation on the third.

Driver takes the goods
Хүргэлтэд гарлаа
delivery_started
2 deliveries ahead
Таны ээлж ойртлоо
delivery_queue_near
Хүргэсэн
Амжилттай хүргэгдлээ
delivery_completed
Any other status
Хүргэгдээгүй шалтгаан
delivery_no_answer, …

Every piece of copy is composed server-side. The browser renders whatever title / body / url the event carries and never writes its own sentence, so wording changes are a config change rather than a frontend deploy.

Source of truth. Templates live in src/services/notifications.py. A status that has no template, or one an operator has muted, still publishes its event — the tracking page refreshes — but nothing pops up and nothing is reported to Deligo.

Two events, one sentence. delivery_started and driver_accepted are the same customer-facing moment reached by two code paths: the driver app starts a route through POST /api/delivery/{sales_id}/start, while a status set straight to wfm 8 arrives through changestatus. Both carry the same body so a customer never reads two different stories about one event.
driver_location is never shown. It fires on every GPS ping and only moves the marker. It is suppressed from push, from the notification log, and from the Deligo report — it is movement, not a message.

4. Queue-position alert

delivery_queue_near is the only notification with no status change of its own to hang off. Nothing in Deligo fires when an order becomes third in line — it becomes third because a different order ahead of it closed. So the map service recomputes the driver's queue after every write that can shorten it.

Triggers

  • POST /api/auth/orders/changestatus — any status change, not only terminal ones. A driver who defers an order has shortened today's queue exactly as much as one who delivered it.
  • POST /api/delivery/{sales_id}/start — the route became real. Without this a one- or two-order route would never alert at all.

Selection

Open orders for the driver are sorted by the driver's confirmed sort_order (orders with none sink to the end — an unsorted order is genuinely last as far as anyone can tell). Every order at position ≤ NOTIFY_QUEUE_ALERT_POSITION that has not already been alerted is notified once.

Why ≤ and not exactly 2. A driver who closes two orders in quick succession, or a route re-sort that moves an order forward, can skip the exact position. With a strict match the customer nearest to being delivered — the one the heads-up is for — is the one who never gets it.

Exactly once

delivery_orders.queue_alert_sent_at records that the alert went out. It is a column rather than an in-memory flag because every API replica evaluates the same queue and would otherwise each send one. The row is marked before the event is published: a crash between the two costs one notification, while the reverse order costs the customer a duplicate on every later status change.

Wording

The count sits inside {queue_position_text} rather than being a literal "2", so raising the threshold cannot make the sentence a lie, and position 0 reads as a different clause instead of "0 хүргэлтийн дараа".

5. Template placeholders

Templates are Python format strings resolved against the event payload. An unknown placeholder renders as an empty string at send time, so the API rejects one on save rather than shipping a blank sentence — a 422 the operator can fix beats a hole in the copy no one notices.

PlaceholderMeaning
sales_numberHuman-facing order code. Defaulted to the sales id when absent.
status_labelMongolian status name for the wfm id.
status_descriptionThe driver's raw note. Prefer the clause below.
status_description_lineReady-made Тайлбар: … clause, empty when there is no note.
queue_positionHow many deliveries are ahead of this one (integer).
queue_position_textReady-made clause for that count, including the zero case.
distance_textDriver's distance, pre-formatted (350 м / 2.4 км).
formatted_addressNew delivery address after a pin edit.
changed_by_nameWho moved the pin.
wfm_status_idNumeric Deligo status id.
admin_title, admin_bodyOperator's manual message.
Why the pre-built clauses exist. A format string cannot say "include this only when it is set". Writing Тайлбар: {status_description} leaves a bare Тайлбар: stranded on every order with no note, so the publisher passes the whole clause — punctuation included — or an empty string.

6. Outbound report to Deligo

Every notification the customer actually sees is reported back to Deligo, so the order's timeline in the main system shows what they were told and when.

POST /api/sales/notification

  
Base URLDELIGO_API_URL (default https://api.deligo.mn)
PathDELIGO_NOTIFY_PATH (default /api/sales/notification)
AuthAuthorization: Bearer <service token>, from POST /api/user/login with DELIGO_API_EMAIL / DELIGO_API_PASSWORD. A 401 forces one re-login and one retry.
Timeout10s
SuccessHTTP 200. Any other status is logged and dropped.

Request body

{
  "id":          "1773113766311954",
  "salesNumber": "ORD-77",
  "eventType":   "delivery_completed",
  "title":       "Хүргэлт амжилттай боллоо",
  "body":        "Таны захиалга амжилттай хүргэгдлээ. Баярлалаа.",
  "urgency":     "high",
  "trackingUrl": "https://map.deligoalpha.mn/track/ORD-77",
  "deviceCount": 2,
  "sentAt":      "2026-08-25T09:18:16.129678+00:00",
  "eventId":     "9f2c1ab34de84f0197c5b1d0a6e2f8ce"
}
FieldTypeNotes
idstringOrder identity — the same sales_id the other /api/sales/* endpoints key on.
salesNumberstringHuman-facing order code. Falls back to id when the event carries none.
eventTypestringOne of the types in §2. Operators can add new ones, so treat it as an open set.
titlestringRendered notification title, after all overrides.
bodystringRendered body, placeholders already substituted.
urgencystringlow | normal | high.
trackingUrlstringPublic tracking link the notification opens when tapped.
deviceCountintegerBrowsers the web push went to. 0 is normal, not a failure — the customer may only ever have had the tracking tab open.
sentAtstringISO-8601, UTC.
eventIdstring32-char hex, unique per notification. Use it to dedupe a retry and to join against the map service's own log.

When it fires

Once per visible notification, from the publish side only. Muted statuses, copy-less events and driver_location return before the report is built, so Deligo never hears about a message nobody saw. Multiple API replicas fan the event out to their own subscribers, but only the publishing worker reports it — one notification, one POST.

Failure behaviour

  • Dispatched to a background thread. The caller is inside the driver's status-change request; a Deligo timeout must not be latency the driver waits out.
  • Never raises. A failed report is a reporting gap; a failed publish is a customer who is not told their driver arrived.
  • No retry queue. A non-200 logs one warning line and is dropped.
Kill switch. Set DELIGO_NOTIFY_PATH= (empty) to stop the reports without a deploy. Worth doing if the endpoint starts failing — the reports are best-effort to us, but a failing one writes a warning line per delivery.

7. Delivery channels

The same rendered notification reaches the customer by two paths, chosen by whether their tab is open.

ChannelReachesNotes
SSE stream Open tracking tab Redis pub/sub fans the event across API replicas. A reconnect replays what was missed via Last-Event-ID; entries older than 15 minutes are dropped so a tab left open overnight does not wake to a burst.
Web Push Closed tab VAPID. Queued on a background thread, never blocking the publish. Requires VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY — without them push is off and the SSE stream still works.

Both carry the same tag (deligo-{sales_id}-{event_type}), so a repeat for one order and event type replaces the previous notification in the OS tray instead of stacking a second one.

8. Operator overrides

Copy resolves through three layers. Later layers win field by field, not whole-template.

  1. Compiled-in defaults — src/services/notifications.py. Render with no network, which is what a driver in a stairwell has.
  2. Environment — NOTIFY_TEMPLATES_JSON, or NOTIFY_<EVENT_TYPE>_TITLE / _BODY / _ICON / _URGENCY. Resolved once per process.
  3. Admin panel — stored in Postgres, merged on every read, cached for NOTIFY_OVERRIDE_TTL seconds per worker.
An admin edit shadows a code change. A template an operator has saved keeps its saved wording even after the default changes in a deploy. To adopt new default copy, revert that template in the admin panel (DELETE /api/push/templates/{event_type}).

Operators can also remap a status to a different event type, or mute it entirely. A muted status still publishes its event — the tracking page refreshes — but nothing is shown, logged, or reported.
